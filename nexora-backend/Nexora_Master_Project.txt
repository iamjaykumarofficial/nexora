# NEXORA — BACKEND DEVELOPMENT PROMPT

Build a complete, production-ready backend for **Nexora**, a modern dating/social connection application.

## Tech Stack

* Node.js
* Express.js
* TypeScript
* MySQL
* Prisma ORM
* JWT Authentication
* OTP-based Authentication
* Socket.IO for real-time communication
* REST APIs
* dotenv
* CORS
* bcrypt where required
* Proper centralized error handling
* Clean modular architecture

---

Create a clean and scalable backend architecture with:

```text
src/
├── config/
├── controllers/
├── middlewares/
├── routes/
├── services/
├── utils/
├── sockets/
└── app.ts
```

Requirements:

* Environment variable configuration
* MySQL database connection
* Prisma integration
* CORS
* JSON parsing
* Centralized error handling
* Standard API response format
* Health check API
* Database health check API
* Proper TypeScript typing
* Development and production scripts

# 2. Authentication

Implement OTP-based authentication.

### APIs

```http
POST /api/auth/send-otp
POST /api/auth/verify-otp
GET  /api/auth/me
POST /api/auth/logout
```

Requirements:

* Mobile/phone based authentication
* OTP generation
* OTP verification
* OTP expiry
* Prevent invalid/expired OTP usage
* Create user after successful verification
* JWT access token
* Authentication middleware
* Protected routes
* Current-user API
* Secure logout/token handling

# 6. Discover System

Build the main dating discovery engine.

Users should be able to discover compatible profiles.

Discovery should consider:

* Profile completion
* Gender preference
* Relationship goal
* Age/preferences where applicable
* Interests
* Existing swipes
* Existing matches
* Blocked users

```http

```

Return profile information suitable for the frontend discovery cards.

# 7. Swipe System

Implement:

```text
Like
Pass
Super Like
```

API:

```http
POST /api/swipes/:targetUserId
```

Example:

```json
{
  "action": "like"
}
```

Requirements:

* Prevent self-swipe
* Prevent invalid users
* Prevent blocked-user interaction
* Prevent duplicate/invalid swipe behaviour
* Track swipe history
* Daily free-user selection limit
* Free plan limit: **10 selections per day**
* Return remaining selection count
* Reset daily usage
* Support like/pass/superlike


# 14. Safety Rules

The backend must enforce:

* Users cannot interact with themselves
* Blocked users cannot interact
* Only matched users can chat
* Only matched users can send date invites
* Users can only modify their own profile/photos
* Users can only read their own notifications
* Users can only manage their own swipes
* Proper JWT authentication
* Input validation
* SQL/ORM safety
* Proper error responses
* No sensitive information exposed in API responses
